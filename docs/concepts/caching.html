Reusing work between runs

Most of what a pipeline does costs money or time: transcription, AI editing decisions, generated video, synthesized speech. Puffin Ship remembers what a step produced so you do not pay for the same work twice. This page explains when that reuse happens, and, just as importantly, when it deliberately does not.

Where reused work lives

Reusable step output belongs to a run group, not to a template. Every run happens inside a group, and a group's saved work is available to later runs in that same group.

That leads to the single most useful thing to know about running templates:

Tip: Clicking ▶ Run on a template deliberately starts fresh. It creates a brand new run group, which has nothing saved yet, so every step runs again and every generated asset is generated again.

To reuse earlier work and avoid paying to regenerate it, open the run group you were working in and run from there, or use ↩ Re-run from this step on a step in the run view. Everything before that step is reused; that step and everything after it runs again.

Both behaviors are intentional. A new video should not inherit another video's decisions, and a second attempt at the same video should not cost full price.

Turning reuse on for a step

Reuse is opt-in per step, with cache: true:

- id: transcribe
  processor: generate_transcript
  input:
    - id: source
      file: speaker-footage
  cache: true

In the editor this is a checkbox on the step. Leave it off for steps you always want fresh, and on for anything expensive.

When a saved step runs again anyway

A saved step is reused only if nothing it depends on has changed. It runs again when:

  • an input file changed
  • an upstream step produced something different
  • the step's own parameters or prompt changed
  • a step listed under cache_deps changed
  • you re-ran from that step, or from a step before it

cache_deps

Sometimes a step depends on another step without reading its output directly. cache_deps makes that dependency explicit so the step is not reused when it should not be:

- id: background
  processor: fill_level
  input:
    - id: source
      file: background-image
  cache_deps:
    - ai_cut           # run again when ai_cut changes, even though we don't read its output
  params:
    duration_step: ai_cut
  cache: true

Without cache_deps, background would keep its old result even after ai_cut produced a shorter timeline.

Re-running from a step

Once a run has finished or failed, each step in the run view gets a ↩ control. It starts a new run in the same group beginning at that step, reusing everything before it. Use it when one decision was wrong and everything up to it was fine, for example when the script is good but the b-roll choices are not.

For AI steps that brainstorm concepts first, ↩ re-picks the concept from the ones already generated, and the ⋯ menu beside it offers Generate new concepts (throw the brainstorm out and start over) or Keep same concept (re-run the step with the concept it already chose).

Clearing saved work

From the template's settings you can clear saved work for the whole template, or from a chosen step onward. Clearing from a step also discards everything after it, because those steps depended on it.

Clearing is the right move when something external changed that Puffin Ship cannot see, such as replacing a file with a different one under the same name.

Generated media is remembered separately

Generated and downloaded media, such as AI clips and avatar takes, is kept alongside your project files rather than as part of a step's saved output, and each generated clip records what it was made for. That is why re-running a step usually reuses the clips it already has instead of paying to generate them all over again, and why deleting a generated clip is enough to have it made afresh.
