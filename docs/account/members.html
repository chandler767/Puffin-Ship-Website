Workspace members and roles

A workspace can be shared. Members see the same files, templates, and run history, so a team can work on one brand together.

Manage members in Workspace Settings → Members.

Roles

There are two roles.

Editor Owner
Upload and organize files Yes Yes
Build and edit templates Yes Yes
Start runs, answer review gates, export Yes Yes
Set workspace variables and service keys Yes Yes
Add, remove, and re-role members No Yes
Rename the workspace No Yes
Change the model training setting No Yes
Delete the workspace No Yes

Editors can do the work; owners also control who is in the workspace and what happens to it.

Adding someone

In Members, use Add member, enter their email address, and choose a role.

The person must already have a Puffin Ship account: adding someone does not send an invitation email or create an account for them. If they do not have one yet, ask them to sign up first, then add them.

Adding someone who is already a member updates their role instead of adding them twice.

Changing a role or removing someone

Owners can change any member's role from the dropdown next to their name, and remove a member with Remove, which asks for confirmation.

A workspace always keeps at least one owner. When there is only one, that person cannot be removed, cannot be changed to editor, and cannot be demoted by re-adding them as an editor from Add member. Their role dropdown is disabled to make that clear. A workspace with no owner would have nobody able to manage members, change settings, or delete it.

To change the last owner, make someone else an owner first. If the workspace has run its course, delete the workspace instead.

Leaving or handing over a workspace

To hand a workspace to someone else, make them an owner, then remove yourself. This is also what you need to do before deleting your account if you own a workspace other people belong to.

Service keys are shared

Service API keys set on a workspace work for every member of it. Anyone in the workspace can start runs that spend against them. Add people you are happy to have spending on your third-party accounts, and keep keys for a smaller circle on a template or run group instead when you need to.

Members never see the value of a saved key, only that one is set.

Deleting a workspace

Workspace Settings → General → Danger Zone deletes the workspace and everything in it: templates, runs, and files. You confirm by typing the workspace name. It cannot be undone.
